# CC Switch v3.21.0

> 这一版的主线是终端工作台与供应商切换的可靠性。内嵌终端学会了 alternate-scroll——opencode 一类全屏 TUI 占用备用缓冲区时，滚轮会被翻译成方向键，终于能滚动了；底部输入框跟随当前选中的终端标签，不再把内容写进上一个会话；三栏布局右侧的模型列表支持整栏折叠（窄条 + 竖排标签，状态持久化），去掉了多余的标题；终端头部统计块终于能显示它测的是哪个模型。供应商切换修复了两个可靠性问题：卡片主点击恢复为切换（此前只剩右键菜单一条路，接管模式下被误读为"切了没反应"）；右键菜单的点击不再冒泡到卡片——此前点「删除」会顺带把该模型切成当前项，然后又被"当前供应商不可删除"挡住，表现为删不掉。崩溃残留的 `live_backup` 不再把所有切换钉死在死代理的热切换路径上。速率统计写入了此前从未存储的模型名，并会丢弃未正常收尾的流留下的旧突发计数。本版新增恢复出厂：设置页新增需输入 RESET 确认的重置入口，一键停止代理、还原全部被接管的客户端配置、备份数据库、清空用户数据并自动重启。**本版不含数据库迁移。**

## 重点内容：你现在可以

- **在内嵌终端里用滚轮滚动 opencode**：opencode 等全屏 TUI 运行在 xterm 的备用缓冲区，那里没有回滚可滚，应用未开启鼠标追踪时滚轮完全无响应；现在滚轮会被按行翻译成方向键序列写入 PTY，与 Windows Terminal 的默认行为一致。普通缓冲区的滚动与 htop 等鼠标感知的 TUI 不受影响。
- **右键菜单里正常删除模型**：菜单是卡片的 DOM 子元素，此前点「删除」会同时触发卡片主点击、把该供应商切换为当前项，随后又被"当前供应商不可删除"拦下。菜单点击现在被完全隔离。
- **左键点击卡片即切换供应商**：主点击恢复了与右键菜单主动作一致的行为；故障转移模式下主点击为加入/移除队列；OMO 与累加模式保留点击固定用量条，避免误触移除/停用。
- **底部输入框永远发给当前选中的终端**：切换标签页后输入不再写进上一个会话；新会话连接完成前会提示会话不可用。
- **折叠右侧模型列表**：与左栏一致，折叠成 32px 窄条 + 竖排文字，重启后记住状态；顶行的用量信息不再被遮挡，多余的「模型列表」标题移除。
- **统计块显示当前模型名**：终端头部的 tok/s 统计块现在显示最近一次请求的模型（此前 tooltip 永远显示"未知模型"），长名自动截断、速率数字不再抖动。
- **一键恢复出厂**（设置 → 高级 → 重置所有配置）：需输入 RESET 确认。流程：停止本地路由并还原 Claude / Codex 等被接管的客户端配置 → 自动备份数据库到 backups 目录（之后可从「备份与恢复」找回）→ 事务内清空供应商、项目方案、提示词、MCP、自定义端点、代理接管状态、用量与会话记录 → 重置应用设置 → 应用自动重启。模型定价种子与技能内容会保留。
- **崩溃后的切换恢复正常**：接管中崩溃会残留 `live_backup` 记录，此后所有切换都走热切换、永远不把真实端点写回客户端配置；现在检测到备份残留且代理未运行时会自动清除并按普通切换处理。
- **速率数值不再被断流污染**：用量解析失败的流不再留下旧的突发计数，下一次生成的实时 tok/s 从零起算，不再卡在偏低的数值上。
- **README 补充终端工作台文档**：三栏工作台（项目、终端实例、会话恢复、Git 更改面板、实时统计、HUD 悬浮窗）的功能说明入册。
