# CC Switch v3.21.0

> 今リリースの主軸はターミナルワークベンチとプロバイダ切り替えの信頼性です。組み込みターミナルが alternate-scroll に対応し、opencode のようなフルスクリーン TUI が代替バッファを使用している間、ホイールイベントが矢印キーに変換されてようやくスクロールできるようになりました。下部のプロンプトは選択中のターミナルタブに追従し、前のセッションの PTY に書き込むことがなくなります。3 カラムレイアウト右側のモデルリストは折りたたみ可能になり（細いストリップ＋縦書きラベル、状態は再起動後も保持）、余分なタイトルは削除されました。ターミナルヘッダーの統計チップは、測定対象のモデル名をようやく表示します。プロバイダ切り替えには 2 つの信頼性修正が入りました。カードのメインクリックが再び切り替えを行い（使用量ピンの書き換え後はコンテキストメニューしか残っておらず、プロキシ引き継ぎ下では「切り替えが効かない」と誤解されていました）、コンテキストメニューのクリックがカードへの誤切り替えに伝播しなくなりました——これによりクリックしたプロバイダが現行になり、「現行プロバイダは削除できません」で削除がブロックされていました。クラッシュで取り残された `live_backup` 行が、すべての切り替えを死んだプロキシのホットスイッチ経路に固定し続けることもなくなります。レート統計はこれまで一度も書き込まれていなかったモデル名を記録し、使用量なしで終了したストリームが残す古いバースト計数を破棄します。新機能としてファクトリーリセットが追加されました：設定ページに RESET 入力で確認するセクションができ、プロキシを停止し、引き継ぎ済みのクライアント設定をすべて復元し、データベースをスナップショットし、ユーザーデータを消去して自動再起動します。**本リリースにデータベースマイグレーションは含まれません。**

## ハイライト：本リリースでできること

- **組み込みターミナルで opencode をホイールでスクロールする**：フルスクリーン TUI は xterm の代替バッファで動き、そこにはスクロールバックがなく、マウストラッキングが無効なときホイールは何もしませんでした。ホイールの移動量は PTY に書き込む矢印キー列に変換され、Windows Terminal の既定動作と同じになります。通常バッファのスクロールや htop のようなマウス対応 TUI には影響しません。
- **コンテキストメニューからモデルを普通に削除する**：メニューはカードの DOM の子だったため、削除をクリックするとカードの切り替えハンドラも発火し、クリックしたプロバイダが現行になって自分自身の削除がブロックされていました。メニューのクリックは現在完全に分離されています。
- **プロバイダカードを左クリックで切り替える**：メインクリックはコンテキストメニューの主操作と同じ動作に戻りました。フェイルオーバーモードではキューへの追加/削除をトグルし、OMO と追加モードのカードは使用量ピンを保持するため、誤クリックで無効化・削除されることはありません。
- **下部プロンプトは常に選択中のターミナルに書き込む**：タブ切り替え後に入力が前のセッションに流れることはなくなりました。新しいセッションが接続されるまで、プロンプトは利用不可と表示します。
- **右側のモデルリストを折りたたむ**：左パネルと同様に 32px のストリップ＋縦書きラベルに折りたため、状態は再起動後も保持されます。ヘッダーの使用量表示はホバーで現れるボタンに隠れず、余分な「モデルリスト」タイトルはなくなりました。
- **統計チップにモデル名を表示**：ターミナルヘッダーの tok/s チップは、最後のリクエストのモデルを表示します（これまでツールチップは常に「未知模型」でした）。長い名前は切り詰められ、100 tok/s 超の速度表示は揺れません。
- **ワンクリックでファクトリーリセット**（設定 → 詳細 → すべての設定をリセット）：RESET の入力で確認します。流れ：ローカルプロキシを停止し、引き継ぎ済みのクライアント設定（Claude / Codex など）をすべて復元 → データベースを backups ディレクトリへスナップショット（後から「バックアップと復元」で復旧可能）→ 1 つのトランザクションでユーザーデータを消去（プロバイダ、プロファイル、プロンプト、MCP、カスタムエンドポイント、プロキシ引き継ぎ状態、使用量とセッション記録）→ アプリ設定をリセット → 自動で再起動。モデル料金シードとスキルの内容は保持されます。
- **クラッシュ後も切り替えが普通に戻る**：引き継ぎ中のクラッシュは `live_backup` 行を取り残し、以後のすべての切り替えをホットスイッチに固定して、実際のエンドポイントをクライアント設定に書き戻さなくなっていました。バックアップがあり、Live に引き継ぎプレースホルダがなく、プロキシが動いていない場合は、行を消去して通常の書き込みにフォールバックします。
- **レート表示が中断されたストリームに汚されない**：使用量の解析に失敗したストリームは古いバースト計数を残さなくなり、次の生成の tok/s は低い値に張り付かずゼロから始まります。
- **README にターミナルワークベンチの説明を追加**：3 カラムワークベンチ（プロジェクト、ターミナルインスタンス、セッション再開、Git 変更パネル、ライブ統計、HUD フローティングウィンドウ）を説明しました。
